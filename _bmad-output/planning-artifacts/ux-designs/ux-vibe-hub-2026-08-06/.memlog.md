- (decision) Sources for this session: PRD (final, already read) + market research + domain research. Brief and technical research (Supabase vs Firebase) excluded as not UX-relevant.
- (decision) Visual posture: evolve the existing prototype visual identity (monochrome black/white/gray, Tailwind defaults, rounded corners, soft shadows) rather than codify as-is or start from scratch. Creative tools (color themes, design directions) in scope.
- (decision) Working mode: coaching path — walk decisions one at a time, use creative tools when visualization helps.
- (decision) Stakes: showcase-grade product — the UI itself is part of the pitch (per PRD S1), not just an internal utility. Design polish matters.
- (decision) Friction with current visual identity: feels too generic/default-Tailwind, lacks personality. User wants evolution toward more distinctive visual identity, not a rebuild.
- (assumption) Research (market + domain) has no concrete visual/branding language for this audience -- color/typography direction must come from user elicitation + creative tools, not research.
- (assumption) Research signals for later EXPERIENCE.md consideration: EU AI Act disclosure requirement for IA chat (credibility/compliance), preference for iterative/step-by-step AI refinement over single-shot prompt->result, and micro-learning/short-session course chunking over long-form. Community/skills-feed differentiator explicitly out of PRD v1 scope -- not building, but noting as known future direction per PRD S9 Q8.
- (decision) FR-3 Course progress: simple fill progress bar on course card (fraction/percent), session-local, sober/factual tone -- not gamified/streak style despite research signal, to stay consistent with product's sober register.
- (decision) FR-4 Admin gate: single shared-password screen gating /admin, session-persisted (no re-entry per click), with a styled in-product error state for wrong code (not a raw browser alert).
- (decision) FR-9 Waitlist visibility: dedicated separate view/screen (not embedded in course-management Admin UI), dashboard/analytics register showing per-tool waitlist counts.
- (decision) AI disclosure (EU AI Act): persistent discreet label/icon near the IA assistant and UI Builder (e.g. 'Assistant IA'), always visible, non-interrupting -- not a one-time dismissible banner.
- (decision) Accessibility floor: target WCAG 2.1 AA (contrast, visible focus, keyboard navigation) -- formal bar, not best-effort only.
- (decision) Outils tab layout: two explicit groups -- 'Disponible' (UI Builder) above, 'Bientot disponible' (waitlist tools) grouped below -- explicit hierarchy rather than a single undifferentiated grid.
- (change) Visual direction pivot: user supplied 3 image references (Dribbble-style playful mobile app mockups -- quiz app, mood-tracker app, 'Move&Sync' fitness app). Overrides earlier 'restrained/monochrome-leaning evolution' framing given to the 4 rendered directions (mono-atelier, warm-studio, precision-console, slate-dark) -- those 4 are now rejected reference, not the direction. New direction: bold, saturated multicolor, playful, illustrated.
- (decision) Illustration: yes to playful illustrations/organic shapes/expressive graphic elements (not just bold type+color structure) -- product should read fun/accessible, not strictly clinical-pro.
- (decision) Palette: franc multicolor -- multiple saturated colors used in color-blocked cards/sections by context or status (not a 1-2 accent-on-neutral system).
- (change) Form factor: overrides implicit desktop-only assumption -- Vibe Hub must also work on mobile/responsive, not desktop-web only. Affects EXPERIENCE.md Foundation and Responsive & Platform sections.
- (decision) Visual pivot scope: applies to the entire product, Landing Page included, not just the Workspace interior. The current monochrome Hero.jsx landing register is fully superseded.
- (change) First bold-playful mockup (direction-bold-playful.html) rejected as 'too AI slop' -- specifically generic sans-serif typography/layout (reads like any AI-generated SaaS template) and flat generic SVG blob decorations. Multicolor functional palette itself was NOT flagged as a problem -- keep. Next iteration needs: a distinctive, characterful display wordmark/heading treatment (closer to the bold condensed/humanist 'Quiz' or italic-leaning 'Move Sync' lettering in the user's references) and more crafted graphic elements (cutout-collage or glossy-3D accents) instead of generic flat SVG blobs.
- (change) v2 mockup (direction-bold-playful-v2.html) rejected entirely -- skewed/condensed system-font typography, colored-accent-letter trick, and collage/glossy decoration all read badly ('pire' than v1). Root cause diagnosed: HTML/CSS mockups constrained to system font stacks cannot fake a real premium display typeface convincingly -- further blind local iteration is unlikely to converge.
